# Forma 3.2 release limits and website rollout

Decision date: 2026-10-27. The maintainer explicitly accepted 0.7 ms of decoder
headroom and one minute of whole-CI headroom. This supersedes the earlier
instruction to continue optimizing 3.2 without a timing exception. It applies
to 3.2.0 and its release candidates; unrelated release lines retain their limits.

The maintainer subsequently directed: “skip what you can that does not compromise
security and get 3.2 released,” explicitly including the soak. Under that later
instruction, the additional 20-run N7 campaign and one-hour active soak are waived
for 3.2.0. Neither is recorded as passed. The limits below remain the accepted
bounds for measurements actually performed; they do not create a new obligation
to run the waived campaign. Stop further performance optimization and additional
prerelease publication solely to obtain soak inputs.

| Measurement | Original target | Accepted 3.2 limit |
| --- | --- | --- |
| N7, nearest-rank p95 of 20 complete whole `npm run check` commands | Strictly below 600 s | Strictly below 660 s |
| Public packed decoder, nearest-rank p95 for each original payload shape | At most 30 ms | At most 30.7 ms |

An N7 pass would still require all 20 original commands to complete successfully. Keep the
ordinary runner, setup, full command, timing boundary and workload unchanged.
Do not replace failed samples, pool campaigns or infer a distribution from one
run. Decoder qualification retains both one-MiB shapes, five warmups and forty
measured fresh documents per shape, four-times CPU slowdown, all raw durations,
value checks, CSP/Trusted Types checks, zero initial writes and refusal controls.
There is no rounding allowance above 30.7 ms and no change to other budgets.

New 3.2 decoder reports identify `public-decoder-p95-3.2-headroom-v1`, the original
30 ms target and the explicit 30.7 ms acceptance bound. The validator still reads
the original profile using its original 30 ms limit. Historical reports and
workflow conclusions remain unchanged, including the 0857163c run's 30.7 ms
failure under the old rule. The authorized tolerance does not complete checks
that never ran after that failure. Complete package qualification is required.

This trades a bounded timing miss for completing the release while retaining
correctness, security, ownership, cleanup, size and artifact-integrity checks.
It is not evidence of a decoder speedup or an infrastructure cause for variance.

## One public stable website update

The maintainer also directed that the next public getforma.dev update happen
after stable 3.2.0 is published. Stop interim preview deployments. Publish the
stable packages, then update and verify the website's package pins, homepage,
documentation, examples and downloads together through the normal OVH flow.
Current documentation and navigation should present 3.2.0, without an RC badge
or a historical-versus-candidate version choice. Preserve historical evidence
and release records without presenting them as current user documentation.

The subsequent streamlining instruction also removes the staged production
rollback exercise from this release's critical path. Keep the existing rollback
mechanism and prior deployment available. Record that the new exercise was not
performed. Final source CI, security and core correctness, independent review
of security-critical release changes, tagged package qualification, archive
integrity/provenance and trusted publication remain required. The overall release
task remains open until the final site deployment and live docs/download checks
pass. No public preview update is needed to satisfy an obsolete sequence.
