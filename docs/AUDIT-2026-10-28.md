# Forma Grand Prix process audit — 2026-10-28

The maintained Grand Prix is `benchmarks/grand-prix` in `getforma-dev/forma`.
This audit started from current main `4c4696c5` after checking the remote on
October 28. It preserves the October 24–25 Round 2 evidence and the original
October 23 experiment. The older 2.x showcase remains prior art only.

## What the latest evidence already established

The benchmark programme drove the FORMA-257–264 work shipped in stable 3.1 and
inherited by 3.2. The current published candidate is 3.2.0 at
`fc76ea8531f0e3a85d0224087384e41f52040e3c`, confirmed against the local tag and
npm registry metadata. **There is no fresh full Grand Prix for 3.2 in this audit.**
The release ancestry and exact claim boundaries are in
[performance history](PERFORMANCE-HISTORY.md) and [the machine-readable ledger](../config/change-ledger.json).

The evidence supports much smaller static HTML, cheaper walker work and large
public-effect improvements. It also retains batching/DOM/adoption costs, missed
row and effect targets, rejected designs and explicit later release exceptions.
An aggregate average must never conceal those results. Consult the ledger's
campaign-specific samples rather than transferring one candidate's times to the
final 3.2 packages.

## Verification performed

- The full dependency-free laboratory/harness test suite passes; see `npm test`
  for the current count. It includes existing budget, transport, browser, CPU
  profile, source-binding and campaign refusal tests as well as the new controls.
- The original archive verifier passes **185 file hashes and 13 original archive
  digests/ZIP checks**. None of those historical files was edited.
- The new SSR validator accepts all **42 actual archived server responses** while
  refusing deliberately corrupted rows/cells in tests. This is compatibility
  validation, not a new timed server race or retroactive qualification.
- Imported final client, qualified server and island campaigns into managed local
  history, with original archives and hashes retained. Reports regenerate from
  original measurements; five-sample client means/spreads reproduce retained data.
- Completed a local diagnostic of frozen Forma 3.0.0 and alien-signals 3.2.1:
  **nine workloads per library, two warmups, five measured samples**, correctness
  passed. It verifies the new lifecycle and does not establish 3.2 performance.
- A qualified server preflight correctly blocked this macOS host, unavailable
  Docker engine and uncommitted work. The attempt remains `blocked/unqualified`.
- Dashboard/report visual inspection at desktop and mobile widths found no
  viewport overflow; dashboard local links and filtering were exercised.
- Registry metadata was checked on October 28; the saved
  [dependency audit](dependency-audit-2026-10-28.json) includes exact response
  sources, current lock versions, available versions and runtime requirements.
  A Preact signals 1.14.5 proposal resolved successfully without changing controls.
  Temporary diagnostic dependencies (12,102,685 bytes) were removed after verification.

## Remaining work and honest boundaries

1. Run the complete current-source/cohort campaign on a suitable native Linux host
   after these source changes are committed. Mac diagnostic data cannot supply
   Linux throughput, startup, memory or browser acceptance.
2. Review and migrate latest competitor majors as separate coherent cohorts.
   The audit found newer Astro, Next, React Router and Preact majors, among others.
   Frozen controls stay frozen. Npm lock resolution alone does not qualify them.
   Rust crates, Docker base digests and browser pins need their own coordinated
   reviews; the npm audit does not claim to check those registries.
3. Server candidate mode currently substitutes Rust crates with controlled
   compiler/app inputs; it is a component experiment. A complete all-package Forma
   3.2 stack campaign must state and pin its compiler/build/core/crate set together.
4. The fixed client before/after order and short sample sets still limit causal
   inference. Future balanced/interleaved campaigns need a prospective protocol
   amendment applied equally to all entrants. New reports make descriptive claims,
   not statistical significance or population-tail guarantees.
5. Docker-stats peaks are sampled container memory, not exact process RSS or
   allocation totals. Startup includes container/probe overhead. Bundle analysis
   covers the static entry graph, not arbitrary lazy-route chunks. Reports keep
   those boundaries visible.
6. Cleanup preserves scientific evidence indefinitely. CI's 30-day artifact
   retention is not a historical archive; promote meaningful runs with original
   ZIPs, hashes and ledger links before expiry. No global cache pruning or deletion
   of unrelated historical checkouts was performed.

## Consolidation decision

Keep the repository-owned Round 2 implementation as the single maintained engine.
Keep frozen experiments, original reports, evidence hashes and rejected outcomes
as historical references. New runs use the application layer. Legacy scoring
scripts remain only to reproduce old publications; they are not the new decision
interface. Do not duplicate the old showcase into a second active benchmark app.
